# Этап 1 — счета, переводы, сверка с банком

## Логика (dist/core/*)

### schema.js
- `OP_TYPES` += `transfer`, `adjustment`.
  - transfer: ровно 2 legs, разные accountId, один < 0, другой > 0, сумма legs = 0; allocations пустые.
  - adjustment: ровно 1 leg, amountCents ≠ 0 (любой знак); allocations пустые; note обязателен (непустой) — объяснение расхождения.
  - income/expense — как раньше, но accountId любого существующего счёта.
- Счёт: добавить необязательное поле `order` (целое, для сортировки; по умолчанию индекс). Валидатор принимает старые данные без `order`.
- `links` у операции: допускается `{feeOf: <id операции перевода>}` у expense (комиссия перевода). Неизвестные ключи links отбрасывать.
- Ограничение: в операцию нельзя записать архивный счёт, если операция новая (проверка в journal, не в validate — старые операции на архивных счетах остаются валидными).

### accounts.js (новый модуль, `MoneyCore.accounts`)
- `KIND_LABELS = {debit:"дебетовая", cash:"наличные", savings:"накопительный", credit_card:"кредитная карта", loan:"кредит", person:"долг человека"}`; в UI этапа 1 доступны первые четыре.
- `addAccount(state, {id, name, kind, openingCents, openingDate})` → state. Имя 1–100 символов, уникально без учёта регистра среди неархивных, иначе ошибка «Счёт с таким названием уже есть.».
- `updateAccount(state, id, patch)` — name/kind/openingCents/openingDate/order.
- `archiveAccount(state, id, archived=true)` — нельзя архивировать последний неархивный счёт («Нужен хотя бы один счёт.»). Архивный счёт скрыт из выбора, но его операции остаются и учитываются в остатках.
- `activeAccounts(state)` — неархивные, по `order`, затем по имени.

### journal.js
- `makeTransfer({id, fromId, toId, amountCents, date, note, now})` → операция transfer (legs: −from, +to).
- `makeFee({id, transferId, accountId, amountCents, date, now})` → expense с `links.feeOf`, note «Комиссия за перевод», allocation `{categoryId:null}`.
- `reconcile(state, accountId, bankCents, date, note, id, now)` → если расчётный остаток счёта на конец дня `date` == bankCents — вернуть `{state, diff:0}` без изменений; иначе добавить adjustment на diff = bank − расчётный, вернуть `{state, diff}`. Пустой note → «Сверка с банком».
- `upsertOperation` при новой операции проверяет, что все её счета неархивные (ошибка «Счёт в архиве.»).
- Удаление перевода (setDeleted) удаляет и связанную комиссию (feeOf) — и восстановление тоже восстанавливает обе.

### views.js
- `balances(state, uptoDate?)` — если передана дата, учитывать только операции с `date <= uptoDate`.
- `totals(state)`: income/expense — только по типам income/expense (transfer и adjustment НЕ входят). balance — как раньше.
- `accountTotals(state)` → массив `{account, balanceCents}` для активных счетов + `{archived: [...]}`.

### Тесты (tests/stage1.test.cjs)
1. Перевод 10 000 Сбер→Т-Банк: Сбер −10 000, Т-Банк +10 000, total не изменился, totals.income/expense не изменились.
2. Перевод с комиссией 50 ₽: total уменьшился ровно на 50, expense +50; удаление перевода удаляет и комиссию, восстановление возвращает обе.
3. Сверка: расчётный 15 300, банк 15 100 → adjustment −200, diff −200; повторная сверка с 15 100 → diff 0, операций не добавилось. Сверка учитывает только операции до даты сверки.
4. Валидация: transfer с одинаковыми счетами, с суммой legs ≠ 0, с 3 legs; adjustment без note или с 0 — ошибки.
5. Архив: нельзя архивировать последний счёт; новая операция на архивный счёт — ошибка; старые операции архивного счёта учитываются в total.
6. addAccount с дублем имени (другой регистр) — ошибка.
7. Миграция v1 и данные этапа 0 продолжают проходить validate без изменений.

## Интерфейс

### Общее
- Форма записи получает третий режим **«перевёл»**: переключатель `[ расход ] [ доход ] [ перевод ]`.
  - расход: поле «откуда» (select счетов), доход: «куда»; по умолчанию — счёт последней операции этого типа, иначе первый активный.
  - перевод: «откуда», «куда» (нельзя одинаковые), сумма, необязательная «комиссия», заметка, дата.
  - Если активный счёт один — select скрыт (форма как раньше).
- Строки журнала: мета показывает счёт: `// расход · Сбер`. Перевод: маркер `[⇄]`, заголовок `Сбер → Т-Банк` (или заметка), сумма без знака цветом --cyan. Корректировка: `[~]`, сумма со знаком цветом --warn, мета `// сверка · Сбер`.
- Фильтры журнала: `[все] [расходы] [доходы] [переводы]` + фильтр по счёту (на десктопе select рядом с поиском; на мобильном — при открытии счёта, см. ниже).
- Правка перевода открывает форму в режиме перевода. Комиссия правится как отдельная операция.
- Box «$ остаток»: сумма = total по активным и архивным счетам (кроме loan/person). Строка «начальный остаток» заменяется на `// счетов: N [счета]` (переход к экрану счетов). Диалог «начальный остаток» убрать (теперь он у каждого счёта).

### Экран «счета» (мобильная вкладка «счета»; на десктопе — секция «// счета [+]» в левом меню со списком счетов и остатками, клик открывает тот же экран в средней колонке вместо журнала)
- box `$ счета`: строки `[▪] Сбер  · дебетовая     15 300,00 ₽`, внизу `// итого 48 420,00 ₽`. Кнопка `[+ счёт]`.
- Тап по счёту → экран счёта: box `$ Сбер` с остатком, кнопки `[сверить с банком]` `[изменить]` `[в архив]`, ниже журнал, отфильтрованный по этому счёту, `[← назад]`.
- `[+ счёт]` / `[изменить]` — шторка (на десктопе — dialog) с полями: название, вид (select из 4 видов), начальный остаток, дата начального остатка.
- `[сверить с банком]` — шторка: «сколько показывает банк?» сумма (может быть отрицательной для кредитной карты), дата (по умолчанию сегодня), пояснение. Показывать живую разницу `// разница: −200,00 ₽`. Кнопка «записать корректировку» (или «всё сходится» при 0).
- Архивные счета — свёрнутая строка `// в архиве: 2 [показать]`, у архивного счёта кнопка `[вернуть из архива]`.
