# Этап 4b (виды регулярных платежей, счётчики) + этап 7 (кредиты)

## A. Виды регулярных платежей — разные окна
`[+ регулярный]` сначала спрашивает вид (5 крупных кнопок), у каждого своя форма:

| вид (`template`) | примеры | сумма | что спрашивает в срок |
|---|---|---|---|
| `subscription` подписка | Netflix, Яндекс Плюс | фиксированная | «списалось?» `[✓]` |
| `fixed` фикс. платёж | интернет, связь, страховка | фиксированная | «списалось?» `[✓]` |
| `bill` по счёту (квартира, ЖКХ, свет, вода) | квартира, свет | **меняется** — примерная для прогноза | «сколько пришло?» + показания счётчиков |
| `income` доход | зарплата, аванс | фикс. или «примерно» | «пришло?» / «сколько пришло?» |
| `loan` кредит | создаётся из кредита (раздел B), вручную не создаётся | по графику | платёж с разбивкой |

### Модель (дополнение к stage-4 schedules)
- `schedule.template`: одно из 5 (старые правила без поля = `subscription`, если subscription:true, иначе `fixed`/`income` по type).
- `schedule.amountMode`: `"fixed" | "variable"`. Для `bill` всегда variable; для income — выбор.
  Для variable `amountCents` — **примерная** сумма (необязательна); оценка для прогноза: медиана последних 3 подтверждённых сумм,
  иначе amountCents, иначе 0 (и пометка «нет оценки»). Функция `schedules.estimate(state, scheduleId)`.
- Статус occurrence для variable: вместо `due/overdue` — `awaiting` («ждёт суммы»), пока не подтверждено/не пропущено.
  Напоминание висит в «ближайших» и плашкой на главном **до тех пор, пока сумму не внесут** (без 60-дневного окна для awaiting).
- Счётчики (только `bill`): `schedule.meters: [{id, name (напр. «свет день», «хол. вода»), unit: "kWh"|"m3"|"gcal"|"unit",
  tariffCents?: целое (копеек за единицу, 2 знака: 6,43 ₽/кВт·ч = 643), archived}]`,
  `schedule.readingsDay?: 1..31` — день, до которого нужно передать показания (напоминание).
- Показания — новый массив `state.readings: [{id, scheduleId, meterId, date, valueMilli (×1000, ≥0), updatedAt, deleted}]`.
  Синхронизация: kind `reading` (добавить в core/sync.js и в белый список worker/util.js SYNC_KINDS — без миграции БД).
- `meters.consumption(state, scheduleId, meterId)` → история `[{date, valueMilli, deltaMilli}]`;
  `meters.costFor(schedule, deltas)` → Σ round(deltaMilli × tariffCents / 1000) по счётчикам с тарифом.
- Валидация: показание не меньше предыдущего по дате (иначе ошибка «Показание меньше прошлого — проверьте»); можно исправить прошлое.

### Окна (UI)
- `bill` в «ближайших»: `24 окт · квартира · ~25 000 ₽ · ждёт суммы [ввести]` (цвет --warn после срока).
  `[ввести]` → шторка «квартира, 24 окт»: если есть счётчики — блок показаний: по каждому `хол. вода: было 123,456 → [ ] м³ · расход 4,2 · 189,50 ₽`,
  итог по счётчикам; поле **«сумма по квитанции»** (предзаполнено оценкой или итогом счётчиков, можно поменять);
  кнопки `[записать платёж]` (создаёт операцию + сохраняет показания) и `[только показания]` (платёж позже — напоминание остаётся).
- Напоминание о показаниях: с `readingsDay − 5` до `readingsDay`: `[!] передайте показания до 25 окт: квартира [ввести]`.
- Экран правила `bill`: история сумм (столбики 12 мес) и расход по каждому счётчику (столбики), тарифы редактируются.
- Прогноз: variable учитываются по оценке, на графике точка полая и в строке `~`.

## B. Кредиты (этап 7)
### Модель
- `state.loans: [{accountId (счёт вида loan), principalCents (сумма кредита), rateBp (годовая ставка ×100: 19,9% = 1990),
  termMonths, startDate (дата выдачи), paymentDay (1..31), method: "annuity"|"diff", scheduleId, updatedAt}]`.
  Остаток долга = остаток счёта loan (отрицательный). Начальный остаток счёта = −principal на startDate.
- Новый тип операции `loan_payment`: `legs: [{accountId: откуда (debit/cash), amountCents: −платёж}, {accountId: кредит, amountCents: +основной долг}]`,
  `allocations` = проценты (+ комиссии) на сумму `платёж − основной долг` (категория `c-loan_interest`, «проценты по кредиту»),
  `links: {loanAccountId, scheduleId?, dueDate?, early?: "term"|"payment"}`.
  Инварианты: основной долг ≥ 0, проценты ≥ 0, Σ allocations = |leg0| − leg1.
  В `totals`/аналитике: расходы = только проценты (основной долг — это перевод себе в погашение долга).
- Стандартная категория `loan_interest` добавляется в DEFAULT_CATEGORIES; `migrate/validate` добавляет недостающие стандартные категории
  по id (а не только когда список пуст).
- `dist/core/loans.js` (`MoneyCore.loans`):
  - `annuityPayment(principal, rateBp, months)`; `calc({principalCents, rateBp, termMonths, method, startDate, paymentDay})` →
    `{payment (для annuity), totalPaid, overpayment, rows:[{n, date, payment, interest, principal, balance}]}` — **калькулятор до оформления**.
  - Проценты по-банковски: `остаток × ставка × дней_в_периоде / дней_в_году` (365/366), последний платёж добивает остаток до 0.
  - `schedule(state, accountId, today)` → график от текущего фактического остатка и даты последнего платежа (перестраивается после
    каждого платежа/досрочки).
  - `split(state, accountId, amountCents, date)` → `{interest, principal}` для платежа в дату (проценты за дни с прошлого платежа).
  - `early(state, accountId, amountCents, date, mode: "term"|"payment")` → операция досрочного погашения (весь платёж в основной долг,
    кроме начисленных процентов) + новый график: `term` — тот же платёж, меньше месяцев; `payment` — тот же срок, меньше платёж.
  - `addLoan(state, {account, loan}, now)` — создаёт счёт loan, запись loans и правило `template:"loan"` (сумма из графика).
- Сверка: `reconcile` уже есть — если банк показывает другой остаток долга, корректировка + перестроение графика.
- Кредитная карта: у счёта `credit_card` необязательный `limitCents` → «доступно = лимит + остаток» на экране счёта и в списке.

### Окна (UI)
- `[+ счёт]` → вид «кредит» открывает форму кредита: сумма, ставка %, срок (мес/лет), дата выдачи, день платежа, тип (аннуитет/дифф.),
  с какого счёта платить. Справа/ниже живой расчёт: `-- платёж 12 848,11 ₽/мес · переплата 171 386,60 ₽ · всего 771 386,60 ₽`.
- Отдельный **калькулятор кредита** (в «планы» или «ещё»): те же поля без сохранения + таблица графика + `[оформить как счёт]`.
- Экран кредита (экран счёта для loan): остаток долга, прогресс-полоса «выплачено X из Y», следующий платёж с разбивкой,
  `[внести платёж]` `[досрочно]` `[сверить с банком]`, таблица графика (сворачиваемая, 12 строк + `[показать все]`),
  итого переплата по текущему графику; история платежей.
- Платёж по кредиту (из «ближайших» или с экрана кредита): шторка с суммой и **редактируемой разбивкой** «проценты / основной долг»
  (предзаполнено `split`, можно вписать цифры из банка — тогда второе поле считается само).
- Досрочка: сумма, дата, `[сократить срок] [уменьшить платёж]`, предпросмотр «было/стало»: срок, платёж, переплата, экономия.
- В журнале: `[%] платёж по кредиту · 12 848 ₽ -- проценты 9 863 · долг 2 985 · Сбер → ипотека`.

## Тесты
- loans: аннуитет 600 000 ₽, 19,9%, 60 мес → платёж ≈ 15 863 ₽ (сверить формулу), сумма строк = principal, последний остаток 0;
  дифф. платёж убывает; split по дням (31/30 дней, високосный год); early term/payment уменьшают переплату; loan_payment валидация и
  totals (проценты = расход, основной долг — нет).
- schedules/meters: variable → awaiting до подтверждения (и старше 60 дней); estimate = медиана последних 3; показания: дельты, стоимость
  по тарифам, ошибка при уменьшении; reading синхронизируется (toRecords/applyRemote).
