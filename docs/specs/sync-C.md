# Синхронизация (этапы B+C): облачная копия + синк устройств

Основа: auth-sync.md (решения: сначала без сквозного шифрования, формат готов к нему — поле `enc`).
Локальное хранение остаётся главным (local-first): приложение работает офлайн, синк — фоном.

## Что синхронизируется
Записи журнала (state): `operations`, `accounts`, `categories` (и на будущее `schedules`, `reserves`, `budgets`, `loans`).
Настройки устройства (тема, язык, приватность, подсказки) — НЕ синхронизируются.
Единица синка — **запись** `{kind, id, updatedAt, deleted, data}`:
- kind: `op` | `account` | `category` | `schedule` | `reserve` | `budget` | `loan`;
- `updatedAt` — ISO время изменения на клиенте. У операций уже есть; для остальных клиент проставляет при каждом изменении
  (поле `updatedAt` в объекте счёта/категории — добавить в schema как необязательное, валидатор принимает старые данные без него);
- `deleted` — для op = op.deleted; для остальных — false (они архивируются, не удаляются);
- `data` — сам объект как в state (для op — целиком с revisions).

## Сервер (Worker + D1)
Миграция `migrations/0002_sync.sql`:
```sql
records(user_id TEXT, kind TEXT, id TEXT, seq INTEGER, updated_at TEXT, deleted INTEGER, enc INTEGER DEFAULT 0,
        data TEXT, device TEXT, PRIMARY KEY(user_id, kind, id));
CREATE INDEX records_seq ON records(user_id, seq);
user_seq(user_id TEXT PRIMARY KEY, seq INTEGER);
```
`POST /api/sync` (сессия обязательна, CSRF как у остальных POST):
- запрос `{cursor: number, device: string, changes: [{kind,id,updatedAt,deleted,data}]}`;
- для каждой change: принять, если записи нет или `updatedAt >= stored.updated_at` (равенство — принять, идемпотентно);
  иначе отклонить как `stale` и вернуть серверную версию в `changes`. Принятым — новый `seq` (атомарно: `user_seq` +1 в batch);
- ответ `{accepted:[{kind,id,seq}], changes:[...записи с seq > cursor, кроме только что принятых от этого device...], cursor: maxSeq, more: bool}`;
  pull пачками по 500, `more:true` — клиент повторяет.
- Ограничения: ≤ 500 changes за запрос, data ≤ 64 КБ, ≤ 100 000 записей на пользователя, kind из белого списка,
  тело запроса ≤ 2 МБ. Ошибки — `{error}`.
- `GET /api/sync/stats` → `{records, lastSync}` для экрана аккаунта.
- `DELETE /api/me/data` → удалить все записи пользователя на сервере (кнопка «удалить облачную копию», с подтверждением в UI).

## Клиент
### Чистая логика `dist/core/sync.js` (`MoneyCore.sync`, тестируется в node)
- `toRecords(state)` → массив записей; `recordKey(r)` = kind+":"+id.
- `diff(prevState, nextState)` → записи, которые изменились (новые / другой JSON / другой deleted) — для очереди отправки.
- `applyRemote(state, records)` → новый state: для каждой записи — вставить, если нет; заменить, если `remote.updatedAt > local.updatedAt`
  (или у локальной нет updatedAt); иначе оставить локальную. Затем `schema.validate`; если весь state не валиден —
  применить записи по одной, пропуская ломающие (вернуть `{state, skipped:[...]}`).
- `mergeFirst(local, remoteRecords)` — первое подключение устройства: объединение по id (то же правило),
  особый случай счёта `main` с нулевым остатком и без операций — берётся серверный.

### Интеграция (app.js)
- Ключ `money.log.sync` в localStorage: `{userId, cursor, device, pending:{"kind:id":true}, lastSync, lastError}`;
  `device` — случайный id устройства, создаётся один раз.
- После каждого `commit(next)`: `diff(prev, next)` → добавить в pending → синк через 1,5 с (debounce).
- Синк: если вошёл и онлайн → отправить pending (пачками по 500) → применить ответные changes (`applyRemote`) → сохранить
  state без повторного попадания этих изменений в pending → повторять, пока `more`.
- Триггеры: старт приложения (после /api/me), после изменений, `visibilitychange` → visible, событие `online`, раз в 60 с при открытой вкладке.
- Первый вход на устройстве (sync.userId пуст или другой):
  - если локальный журнал пуст → просто скачать всё;
  - если не пуст и на сервере есть данные → шторка/диалог: `[объединить]` (mergeFirst, рекомендуется) / `[заменить данными из облака]` /
    `[отмена — не синхронизировать]`;
  - если на сервере пусто → отправить всё локальное.
  - если sync.userId принадлежит ДРУГОМУ пользователю → тот же диалог, но по умолчанию «заменить» не выбирать без подтверждения.
- Выход: синк останавливается, cursor/pending очищаются, локальные данные остаются.
- Индикатор в топбаре слева от глаза: `[sync ✓]` / `[sync …]` / `[offline]` / `[sync !]` (ошибка, тап — повторить), только когда вошёл.
  На мобильном — короткий значок `✓/…/!` (тач-цель 44px). Подсказка aria-label.
- Box «аккаунт»: `-- облако: 182 записи · синхронизировано 2 мин назад`, `[синхронизировать сейчас]`, `[удалить облачную копию]` (подтверждение).
- Аватар: если нет картинки или она не загрузилась — квадрат с первой буквой имени (цвет --accent на --panel).
- Строку `// хранится в этом браузере. // без аккаунта и синхронизации.` в меню показывать только без входа; при входе — `-- синхронизация включена`.
- Service worker: `/api/*` не кэшировать (уже так).
