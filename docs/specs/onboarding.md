# Вход на главном экране и выбор ника

## Главный экран (журнал), если не выполнен вход и не нажато «позже»
Box над «$ остаток» (на мобильном — первым):
```
$ finance.log
[ok] журнал загружен · записи хранятся на этом устройстве
-- войдите, чтобы синхронизировать телефон и компьютер
[войти через Telegram]  [войти через Google]        [позже]
```
- Кнопки — как в блоке аккаунта (те же ссылки /api/auth/*/start). Telegram скрыт, если `/api/config` → telegram:false.
- `[позже]` → `settings.onboardingDismissed = true` (boot.js), блок больше не показывается; вход остаётся в настройках.
- Офлайн / сервер недоступен → блок не показывать.

## Выбор ника после входа
- Миграция `migrations/0004_handle_confirmed.sql`: `ALTER TABLE users ADD COLUMN handle_confirmed INTEGER DEFAULT 0;`
- `/api/me` → `user.handleConfirmed` (bool). `PATCH /api/me {handle}` ставит `handle_confirmed = 1`. Новый `POST /api/me/handle/confirm` — подтвердить текущий без изменения.
- `GET /api/handle/check?h=<ник>` (сессия обязательна) → `{ok:true}` | `{error:"bad_handle"|"handle_taken"}` (свой текущий ник считается свободным). Лимит частоты не нужен, но debounce на клиенте 300 мс.
- Если после входа `handleConfirmed === false` — шторка (мобильный) / диалог (десктоп) **до** диалога синхронизации:
  ```
  $ выберите ник
  -- так вас будут видеть: finance.log@<ник>
  @[ glupismeshon            ]   -- свободен ✓ / занят / только a–z 0–9 _ -, 3–24
  [сохранить]   [оставить @glupismeshon]
  ```
  поле предзаполнено текущим (автоназначенным) ником, ввод приводится к нижнему регистру, `inputmode="text" autocapitalize="none" autocorrect="off" spellcheck="false"`.
  После сохранения — заголовок-анимация сразу показывает новый ник, затем (если нужно) диалог синхронизации.
- Существующие пользователи (handle_confirmed = 0) увидят шаг один раз — это нормально.
