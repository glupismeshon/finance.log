# Этап 3 — чеки, тепловая карта, аналитика покупок

## 1. Чеки: модель

Чек — это **одна покупка** (одна expense-операция, одна проводка по счёту), внутри которой позиции.
Позиции **никогда не трогают баланс**: они только раскладывают сумму покупки по категориям (allocations).

### Поле операции `items` (только у expense, необязательно)
```
items: [{
  id,                 // строка, уникальна в пределах операции
  kind: "item" | "discount" | "fee",   // товар | скидка | доставка/сервис/чаевые
  name,               // 1–80 символов (для discount/fee — можно пусто → UI покажет «скидка»/«доставка»)
  qtyMilli,           // количество ×1000 (целое > 0): 2 шт = 2000, 0,4 кг = 400; для discount/fee = 1000
  unit,               // "pcs" | "kg" | "g" | "l" | "ml" | "pack"  (для discount/fee = "pcs")
  amountCents,        // сумма строки, целое > 0 (скидка тоже положительная — знак задаёт kind)
  categoryId          // null | категория вида expense (для discount/fee игнорируется → null)
}]
```
- Цена за единицу не хранится — вычисляется: `amountCents * 1000 / qtyMilli` (для кг/л — за 1 кг/л; для г/мл — пересчёт на кг/л).
- Инвариант: `Σ item − Σ discount + Σ fee = |leg|` (сумма покупки). Иначе валидатор отвергает.
- `allocations` у операции с items **строятся из items** функцией `journal.allocationsFromItems(items, fallbackCategoryId)`:
  1. товары группируются по categoryId (null → fallbackCategoryId операции, т.е. выбранной для покупки категории);
  2. скидка распределяется по группам пропорционально их сумме (метод наибольшего остатка, в копейках — итог точно сходится);
  3. fee добавляется к группе fallbackCategoryId (или null).
  Результат — allocations с суммой = |leg|; группы с нулём выбрасываются.
  Валидатор проверяет, что allocations операции с items совпадают с этим расчётом (порядок по categoryId, null последним).
- Если пользователь вводит итог чека вручную и он не совпал с суммой позиций — UI предлагает:
  `[скидка −120 ₽]` `[доставка +120 ₽]` `[исправить итог на 1 000 ₽]` (см. UI). Расхождение без объяснения сохранить нельзя.

### Память товаров (`suggest.js`)
- `itemKey(name)` — как merchantKey.
- `items(state, merchantKey|null, prefix, limit=8)` → `[{name, unit, lastAmountCents, lastQtyMilli, lastUnitPriceCents, categoryId, count}]`
  — сначала товары этого магазина по частоте, затем остальные; фильтр по началу любого слова.
- Последняя цена — **подсказка**, в поле не подставляется автоматически (кроме кол-ва/ед./категории).

### Валидация (тесты)
1. Чек из ТЗ: молоко 2 шт 240, курица 1 кг 420, макароны 2 уп 180, шампиньоны 400 г 160 = 1 000 ₽, одна проводка −1000; баланс −1000 ровно один раз.
2. allocationsFromItems: молоко→молочка 240, курица→мясо 420, макароны (null→fallback «продукты») 180, грибы→овощи 160.
3. Скидка 100 на чек 1000 (600 мясо + 400 молочка) → 540 / 360; скидка 1 копейка на 3 равные группы — сумма сходится.
4. fee 150 → в fallback-категорию.
5. Отвергается: Σ ≠ |leg|; items у income; qtyMilli 0; amountCents ≤ 0; неверный unit; allocations не совпадают с расчётом.
6. suggest.items: после двух чеков в «Пятёрочке» с «молоко» — подсказка по префиксу «мол», lastUnitPriceCents верный, товары «Пятёрочки» выше чужих.
7. Правка чека (изменили кол-во) → ревизия, allocations пересчитаны, баланс изменился ровно на разницу.

## 2. Аналитика: представления (`views.js` / новый `analytics.js`, `MoneyCore.analytics`)
Все функции берут только неудалённые операции; переводы и корректировки в расходы/доходы не входят.
- `daily(state, {from, to, type:"expense"|"income"|"net", accountId?})` → `{ "YYYY-MM-DD": cents }`.
- `heatLevels(values)` → пороги 4 уровней по квантилям ненулевых дней (25/50/75%), чтобы одна большая покупка не «гасила» остальные.
- `summary(state, {from, to})` → `{expense, income, net, days, avgPerDay, ops, avgCheck}` и то же для **предыдущего периода такой же длины** + дельты в %.
- `byCategory(state, {from, to, parent:true})` → `[{id, cents, share, prevCents, delta}]` (prev — предыдущий период).
- `byMerchant(state, {from, to, limit})` → `[{merchant, cents, count, avgCheck, lastDate}]`.
- `byItem(state, {from, to, limit, sort:"cents"|"count"})` → `[{name, cents, count, qtyMilli, unit, firstUnitPrice, lastUnitPrice, priceDelta}]`.
- `monthly(state, {months:12, to})` → `[{month:"YYYY-MM", expense, income}]`.
- `weekday(state, {from, to})` → средний расход по дням недели (пн…вс).
Тесты на каждую функцию с фиксированными датами (todayISO параметром, не Date.now).

## 3. UI

### Чек в форме расхода
- Под полем суммы ссылка `[+ чек]` / `[+ receipt]` → раскрывает редактор позиций внутри шторки.
- Строка позиции (мобильный — в две строки):
  `название (автодополнение)` / `кол-во` + `ед.` (селект шт/кг/г/л/мл/уп) / `сумма строки` / категория-чип (по умолчанию — категория покупки) / `[×]`.
  Под названием серым: `// в прошлый раз 1 кг · 420 ₽ (420 ₽/кг)`.
- `[+ позиция]`, `[+ скидка]`, `[+ доставка]`.
- Итог: если пользователь не трогал поле «сумма» — оно автоматически = Σ позиций (поле становится только для чтения с пометкой `// из чека`).
  Если ввёл сумму сам и она ≠ Σ — красная строка `// расхождение −120,00 ₽` и три кнопки (скидка / доставка / исправить итог). Сохранение блокируется до выбора.
- В журнале покупка с чеком: мета `// 4 позиции · продукты · Сбер`; тап — правка (чек раскрыт).
- Экран деталей не нужен — правка открывает тот же редактор.

### Вкладка «анализ» (новая, между «счета» и «планы»; на десктопе — пункт меню, экран в средней колонке)
Box `$ анализ` с периодом: `[месяц] [3 мес] [год]` + стрелки `[←] [→]` для сдвига периода; подпись `// окт 2026 vs сен 2026`.
1. **Сводка**: потрачено / получено / сальдо / в среднем в день / средний чек — каждое с дельтой к прошлому периоду (`▲ 12%` цветом --over для роста расходов, --accent для снижения).
2. **Тепловая карта** (GitHub-стиль): колонки — недели, строки — пн…вс, клетка 11px с зазором 3px, скругление 2px.
   Цвет: уровень 0 = --panel, 1–4 = смесь --accent с --bg 25/50/75/100%. Подписи месяцев сверху, `пн ср пт` слева.
   Переключатель `[расходы] [доходы]`. Период карты — всегда последние 53 недели (на мобильном горизонтальный скролл, прокручено к сегодняшнему дню).
   Тап по клетке → подсказка `// 20 окт · 3 850 ₽ · 4 записи [показать]` → `[показать]` открывает журнал с фильтром по этому дню.
   Под картой легенда `меньше ▢▢▢▢▢ больше` и строка `// дней без трат: 12 · самый дорогой день: 14 окт, 12 400 ₽`.
3. **Категории**: горизонтальные полосы (ширина = доля), название, сумма, доля %, дельта; тап по родителю раскрывает детей. Цвет полос — --accent (одна заливка, не радуга).
4. **Магазины**: топ-10 — сумма, кол-во покупок, средний чек.
5. **Товары** (если есть чеки): топ по сумме и по частоте (переключатель); у товара — изменение цены за единицу `молоко 120→135 ₽/шт ▲ 12%`.
6. **По месяцам**: 12 столбиков расходов (и тонкой линией/точками доходы), подпись месяца снизу; тап по столбику — переход к этому месяцу.
7. **Дни недели**: 7 полос среднего расхода.
Графики — инлайн SVG, без библиотек, цвета только из CSS-переменных темы (работают во всех 23 темах).
Перед кодом графиков загрузить скилл `dataviz` и следовать его правилам (подписи, доступность, без лишних цветов).
